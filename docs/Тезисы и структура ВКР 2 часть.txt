Структура второй части ВКР
ЧАСТЬ 2. РАЗРАБОТКА И РЕАЛИЗАЦИЯ МЕТОДИКИ ФОРМИРОВАНИЯ ЗДОРОВЫХ ПРИВЫЧЕК В ТЕЛЕГРАМ-БОТЕ

Введение во вторую часть

Краткое повторение проблемного поля, выявленного в первой части: неэффективность существующих решений, отсутствие глубинной геймификации, персонализации и настоящей наставнической поддержки.
Формулировка цели второй части: описать разработку и архитектуру Telegram-бота, реализующего комплексную методику формирования привычек, основанную на синтезе игровой психологии и анонимной наставнической поддержки.
Задачи части:
Обосновать выбор платформы и технологического стека.
Разработать архитектуру и функциональные требования к системе.
Реализовать ключевые модули: личный кабинет, систему привычек, геймификацию, аналитику и модуль наставничества.
Описать механизмы измерения эффективности и план экспериментальной проверки.
Глава 2.1. Выбор платформы и технологий для разработки

2.1.1. Обоснование выбора платформы Telegram:
Низкий порог входа: Пользователям не нужно скачивать новое приложение.
Высокая вовлеченность: Пользователи постоянно находятся в мессенджере, уведомления не игнорируются.
Кроссплатформенность: Доступ с любого устройства.
Мощный API для ботов: Широкие возможности для создания интерактивного интерфейса (кнопки, меню, inline-режим).
Встроенные социальные features: Возможность легко интегрировать групповые чаты и каналы для сообщества.
2.1.2. Обоснование принципа Open Source:
Прозрачность и доверие: Пользователи и эксперты могут проверить код, что важно для тем, связанных с психологией и данными.
Сообщество и развитие: Возможность для других разработчиков и исследователей вносить вклад, улучшать проект, создавать форки.
Доступность и кастомизация: Любой пользователь (или организация) может развернуть своего собственного бота с персональным набором привычек и конфигурацией, как и планировалось.
2.1.3. Выбор технологического стека:
Backend: Python (как наиболее популярный и удобный для быстрой разработки ботов, с богатыми библиотеками для AI и анализа данных).
Фреймворк для бота: python-telegram-bot (асинхронный, хорошо документированный).
База данных: PostgreSQL / SQLite (для хранения структурированных данных о пользователях, привычках, прогрессе).
Хранение конфигов: JSON/YAML-файлы (для легкой кастомизации программ привычек без изменения кода).
Контейнеризация: Docker (для упрощения деплоя и запуска форков).
Глава 2.2. Архитектура и функциональные модули системы

Диаграмма архитектуры системы (блок-схема)
2.2.1. Ядро системы (Core):
Обработчик входящих сообщений и команд.
Менеджер состояний пользователя (State Machine).
Модуль работы с базой данных (ORM).
2.2.2. Модуль личного кабинета пользователя:
Регистрация и onboarding (анкетирование для первичной персонализации: цели, уровень активности, предпочтения по времени).
Профиль пользователя: текущие активные привычки, статистика, уровень, достижения.
Настройки: время уведомлений, выбор куратора (AI/анонимный человек), уровень детализации отчетов.
2.2.3. Модуль управления привычками:
Каталог готовых привычек: Пользователь может подписаться на готовые программы ("Утренняя зарядка", "Питьевой режим", "Осознанность").
Конструктор кастомных привычек: Пользователь полностью создает свою привычку: название, описание, периодичность, время напоминаний.
Система конфигурационных файлов (JSON/YAML): Описание для Open Source-форков:
Структура файла: название программы, описание, массив привычек в рамках программы.
Для каждой привычки: текст напоминаний, вопросы для рефлексии, motivational quotes, условия получения достижений (бейджей).
Пример фрагмента конфиг-файла.
2.2.4. Модуль геймификации:
Система прогресса и уровней (очки опыта за выполнение действий и рефлексию).
Система достижений (бейджи) за последовательность, разнообразие, итоговые цели.
Визуализация прогресса: графики и диаграммы прямо в чате (использование библиотек для генерации изображений).
Элементы нарратива: история или миссия, в которую вписано путешествие пользователя.
2.2.5. Модуль аналитики и отчетности:
Трекинг показателей:
Вовлеченность: % выполненных привычек от всех запланированных.
Динамика: изменение вовлеченности по неделям/месяцам.
Консистентность: длина самой длинной серии (streak).
"Сложные дни": дни недели/время суток, когда пользователь чаще всего пропускает привычки.
Формирование отчетов:
Еженедельный персональный отчет в чат: статистика, графики, похвала за прогресс, анализ слабых мест.
Возможность запроса отчета по требованию.
2.2.6. Модуль наставнической поддержки:
Два режима на выбор пользователя:
Анонимный чат с куратором (человеком): Система рандомно соединяет пользователей, давших согласие на роль куратора, с теми, кто нуждается в поддержке. Реализация правил и модерации для безопасности.
Искусственный интеллект (AI-куратор): Чат-бот на основе LLM (например, GPT), который обучен давать поддерживающие, мотивирующие ответы, основанные на прогрессе пользователя. Акцент на эмпатию и технику мотивационного интервьюирования.
Триггеры для подключения наставника: после серии пропусков, при падении мотивации (на основе анализа текста рефлексии), по запросу пользователя.
Глава 2.3. Методика экспериментальной проверки эффективности

2.3.1. Формулировка гипотез:
Основная гипотеза: Использование Telegram-бота с интегрированной методикой (глубокая геймификация + наставническая поддержка) приводит к статистически значимому повышению уровня вовлеченности и консистентности в формировании привычек по сравнению с использованием стандартных трекер-приложений.
Дополнительные гипотезы:
Группа пользователей с доступом к наставнической поддержке (любой формы) покажет на X% более высокую ретенцию (удержание) через 30 дней, чем группа без нее.
Пользователи, создавшие кастомные привычки, будут демонстрировать более высокую вовлеченность по этим привычкам, чем по готовым из каталога.
Внедрение элементов нарратива увеличивает среднее время взаимодействия с ботом на Y%.
2.3.2. План эксперимента:
Выборка: Привлечение 2-х групп добровольцев (по 50-100 человек в каждой) через тематические сообщества.
Группа 1 (Контрольная): Использует базовую версию бота (только трекинг привычек и напоминания, без геймификации и наставничества).
Группа 2 (Экспериментальная): Использует полную версию бота со всеми реализованными модулями.
Продолжительность: 8-12 недель (достаточно для формирования начального автоматизма).
Методы сбора данных: Автоматический сбор метрик самим ботом + добровольные pre-/post-опросники (например, шкала самоэффективности, уровень мотивации).
2.3.3. Ключевые метрики для оценки эффективности (Что замеряем?):
Retention Rate: % пользователей, остающихся активными через 1, 4, 8 недель.
Engagement Rate: Средний % выполненных привычек от всех запланированных на пользователя в неделю.
Average Streak Length: Средняя длина самой длинной серии подряд идущих выполненных привычек.
User Satisfaction: Оценка удовлетворенности по итоговому опросу (NPS или 5-балльная шкала).
Количество обращений к модулю наставничества и его субъективная оценка полезности.
2.3.4. Ожидаемые результаты и их интерпретация:
Ожидается, что экспериментальная группа покажет лучшие результаты по всем количественным метрикам.
Качественный анализ фидбека от пользователей поможет понять, какие именно элементы (геймификация, поддержка, кастомизация) оказали наибольшее влияние.
